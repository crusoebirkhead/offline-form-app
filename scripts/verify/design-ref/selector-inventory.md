## Generic per-component wrapper (applies to every component type)

Emitted by `component/form.js` (core wrapper) + `field/form.js` (label/element/description
composition) + `label/form.js` (the `<label>` itself), composed by each
component's own template for the "element" slot. ✓ VERIFIED by reading all three files.

```
div#<instanceId> [ref="component"]
  class = "<mb-2*> formio-form-group has-feedback formio-component formio-component-<type> formio-component-<key> [formio-component-multiple] [<customClass>] [required] [formio-component-label-hidden] [formio-hidden]"
    <label ref="label" class="col-form-label [<label.className>] [field-required]" for="<id>-<key>" id="l-<id>-<key>">…</label>   -- only if !label.hidden && labelPosition !== 'bottom'
    <element>                                                     -- the component's own input markup (input/select/radioGroup/etc.)
    <div class="form-text text-muted" id="d-<id>-<key>">…</div>   -- only if component.description set
  <div class="formio-errors invalid-feedback" ref="messageContainer"></div>
```

- `mb-2` prefix: NOT in `@formio/standard-template` at all (confirmed absent
  from `assets/webview/assets/formio-standard-template.js.txt` via grep). It
  comes from core `Component.className` calling
  `this.transform('class', 'form-group')` (`Component.js:1694`), which the
  gryphon/bootstrap5 transform table maps `form-group` → `formio-form-group`
  (string literal found in `assets/webview/assets/formio.form.min.js.txt`:
  `"form-group":"formio-form-group"`) — the `mb-2` token itself is a Bootstrap
  spacing utility class added by the same transform pipeline. Net result on
  every input-bearing component: `class="mb-2 formio-form-group has-feedback formio-component formio-component-<type> ..."`.
  ✓ VERIFIED against the literal HTML dump (`ert2jpf` node in synthetic-day-desktop.html: `class="mb-2 formio-form-group has-feedback formio-component formio-component-textfield formio-component-prefix"`).
- `formio-component-<key>` — only added `if (this.key && this.key !== 'form')` (`Component.js:1697-1699`).
- `formio-component-multiple` — added when `component.multiple` is true.
- ` required` (leading space, own class token) — added when
  `component.validate.required` is truthy AND `hasInput` (`Component.js:1706-1708`).
- ` formio-component-label-hidden` — added by `labelIsHidden()` (see Required/hidden section below).
- ` formio-hidden` — added when `!this.visible` (conditional logic hiding), **not**
  the same as the dedicated `type: "hidden"` schema component (see Hidden-type section).
- Components without input (`hasInput === false`, e.g. panel/columns/htmlelement)
  do **not** get `has-feedback` / `formio-form-group` — only
  `formio-component formio-component-<type> ...`.

### Label position
`field/form.js` places `labelMarkup` **before** `element` unless
`label.labelPosition === 'bottom'`, in which case it's placed **after**. Default
is before (top). ✓ VERIFIED (`lib/templates/field/form.js` line 9 vs the trailing
condition).

### Description
`.form-text.text-muted` div, id `d-<instanceId>-<key>`, only rendered
`if (component.description)`. Input also gets `aria-describedby="d-<id>-<key>"`
pointing at it. ✓ VERIFIED (`lib/templates/field/form.js`, `lib/templates/input/form.js`).

## HIDDEN-type fields (schema `type: "hidden"`) vs conditionally-hidden

Two distinct mechanisms — do not conflate:

1. **Dedicated Hidden component** (`node_modules/@formio/js/lib/mjs/components/hidden/Hidden.js`):
   `labelIsHidden()` hard-overridden to always return `true` (line 42-44); its
   `inputInfo.attr.type = 'hidden'` renders a native `<input type="hidden">`.
   Wrapper still gets the standard `formio-component formio-component-hidden`
   classes (has-feedback/formio-form-group etc. — it `hasInput`), so it
   contributes layout space (margin/padding) by default even though its
   content is invisible.
2. **Conditionally-hidden component** (any type, hidden via conditional logic
   / `!this.visible`): wrapper gets ` formio-hidden` appended
   (`Component.js:1712-1714`).

`formio-theme.css:151-153` collapses BOTH:
```css
.formio-hidden,
.formio-component-hidden {
  display: none !important;
}
```
This fix was added in commit `35ed7c4` (FORM-2) specifically because the
dedicated Hidden component's `.formio-component-hidden` wrapper was NOT
originally covered by the `.formio-hidden` rule and kept contributing
Bootstrap `mb-*` margin to the flex layout. ✓ VERIFIED via `git show 35ed7c4`.
Sibling-spacing rule also excludes both:
`.formio-component + .formio-component:not(.formio-hidden):not(.formio-component-hidden)`.

`day`-type components also render a NAME-clashing native
`<input name="data[day]" type="hidden" class="form-control" ref="input">`
INSIDE their own wrapper for the composite value (`lib/templates/day/form.js`
line 20) — this is unrelated to the dedicated Hidden component but shares the
`type="hidden"` attribute; do not select on `input[type="hidden"]` alone
expecting only top-level Hidden components — Day emits one too, nested under
`.formio-component-day`. ✓ VERIFIED live: `<input name="data[day]" type="hidden" class="form-control" ... ref="input">` inside `#ebrmvts.formio-component-day`.

## Runtime DOM mutations performed by `form-shell.html`

1. **`injectPlaceholders()`** (`form-shell.html:62-68`, re-run via
   `MutationObserver` on every DOM change under `#formio-container`): for
   every `.form-control` lacking a `placeholder` attribute, sets
   `placeholder=" "` (single space). Purpose stated in the adjacent comment:
   enables the CSS `:not(:placeholder-shown)` floating-label trick, since that
   pseudo-class only activates when a `placeholder` attribute exists at all.
   Net effect: **every** `.form-control` in this app's rendered forms carries
   `placeholder=" "` unless it already had a real placeholder — confirmed live
   on `input[name="data[prefix]"]`, day/month/year inputs, and the flatpickr
   text input in the dump (all show `placeholder=" "`).
2. **`enableDataGridLabels(schema)`** (`form-shell.html:75-82`, run once on the
   schema BEFORE `Formio.createForm`, not a DOM mutation but a schema
   mutation): recursively walks `schema.components`; for every direct child of
   a `type: "datagrid"` node, sets `child.dataGridLabel = true`. This flips
   `Component.labelIsHidden()`'s datagrid branch
   (`(this.isInDataGrid && !this.component.dataGridLabel)` — Component.js:889)
   from hidden to shown, so every datagrid cell renders its own `<label>`
   instead of relying solely on the shared `<thead>` column-name row. This is
   why `formio-theme.css` (FORM-4 comment, lines 1663-1673) hides
   `.datagrid-table thead` entirely and stacks cells as full-width fields with
   their own labels — the header row would otherwise be redundant/duplicated
   info once every cell has its label.
   ✓ VERIFIED: `dataGridLabel: false` is the core default
   (`Component.js:97`), Checkbox overrides it to `true` by default
   (`Checkbox.js:11` — checkboxes always show their own label even ungridded),
   all other types default `false` and rely on this app's shell override.

**CRITICAL GOTCHA — CDN dependency**: `CalendarWidget.js` (`@formio/js`) loads
flatpickr's CSS and JS via `Formio.requireLibrary(...)` pointed at
`Formio.cdn['flatpickr-formio']` / `Formio.cdn['flatpickr']`
(`node_modules/@formio/js/lib/mjs/widgets/CalendarWidget.js:125-146`) — i.e.
**flatpickr is NOT bundled in this repo's `node_modules` or
`assets/webview/assets/`** (confirmed: no `flatpickr` package found anywhere
under `node_modules`, and `form-shell.html` sets no `Formio.cdn` override).
In a genuinely offline WebView, opening a datetime field's calendar popup may
silently fail to load its CSS/JS. This is an operational risk independent of
CSS theming, but it means: (a) the popup's styling cannot be locally verified
without network access, and (b) theme authors should not assume the calendar
popup classes are reliably present at runtime in this "offline app" without
separately confirming a CDN override or local flatpickr bundle exists.
✓ VERIFIED via source read of `CalendarWidget.js` lines 125-127, 146; no
counter-evidence of a bundled/offline flatpickr found anywhere in the repo.
